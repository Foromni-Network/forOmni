# Security Policy

Foromni values the safety, privacy, and trust of everyone who participates.

## Reporting a vulnerability

Please do not publish exploitable vulnerabilities, credentials, access tokens, private keys, or sensitive personal information in public issues or pull requests.

Use GitHub's private vulnerability reporting feature for this repository if enabled. Otherwise, contact the repository owners through the private contact method listed on the Foromni organization profile and include:

- A concise description of the affected component.
- Steps to reproduce, where safe.
- Potential impact and affected versions or commits.
- Any suggested mitigation.

Do not access, modify, or disclose data that does not belong to you while investigating a suspected issue.

## Maintainer response

Maintainers will acknowledge reports when practicable, assess severity and scope, coordinate a fix, and agree on disclosure timing with the reporter. Do not assume a report is resolved until maintainers confirm the fix and release status.

## Security expectations for contributions

- Never commit secrets or production credentials.
- Use least-privilege access and explicit authorization.
- Keep human approval gates for sensitive or consequential actions.
- Protect member data through data minimization, access controls, and clear retention practices.
- Treat external content, agent output, and tool results as untrusted input.
- Document security-relevant changes and dependencies.

This policy is an initial baseline and will be expanded as the project establishes its operational security process.
