## 1. Identity and custody decisions

| Principal | May read | May write | Must never control |
|---|---|---|---|
| Founder/authorized requirements reviewer | Proposed full contract, outcomes, full-cost ledger | Approval record for requirements/trial | Privately held coder secret or silent grading overrides |
| Untrusted coding worker | Public behavior and assigned source, synthetic non-sensitive fixtures | Patch in isolated disposable workspace | QA holdouts, oracle, merge authority, trusted grants, release |
| Trusted source observer/broker | Candidate Git remote refs + source history; task-grant state | Source evidence and controlled candidate actions only if later authorized | Independent QA judgment or publication of raw secrets |
| Independent evaluator | Exact frozen candidate source, fixtures, hidden test oracle, result evidence | Isolated report store and verified verdicts | Editing candidate source while granting itself a pass; protected merger |
| Protected integrator (future) | Review of actual merged/prospective SHA and authorized QA verdict | Source promotion only under host-enforced protection and approval | Authoring evaluator fixtures |
| Release authority (future) | Accepted integrated SHA/artifacts and approved staging policy | Separately authorized release and rollback | Changing frozen benchmark result after observation |

**Enforcement requires separate authenticated credentials, filesystem/network boundaries and trustworthy audit of writes.** Merely assigning different agent names or separate chat sessions is not isolation. A shared GitHub App may represent many workers; only a trusted broker can provide internal identity mapping and action-time scope checks.

## 2. Evidence record for each verdict

```text
Trial identity:
  trial_id; arm; objective/contract revision; approval reference
Actor:
  registry_agent_id; independently authenticated incarnation_id; task/attempt_id
Source:
  repository identity; base_sha; candidate_sha; independently observed evaluated_sha
  prospective_merge_sha (null if none); working-tree cleanliness and diff digest
Evaluator provenance:
  evaluator authenticated principal; suite version/digest; fixture version/digest
  runtime image digest; exact migration revision; clock T0; browser/version/viewport
Actual execution:
  positive_cases_expected/run; negative_cases_expected/run
  per-case real process exit and assert result; redacted log/artifact digest
  failed/unknown/infra-error reasons with timestamps
Security:
  permission decision source + revision; blocked high-severity cases; reviewer notes
Economics:
  full model/tool/runner/CI/human cost including retries and failed attempts
Convergence:
  actual GitHub ref/read-back; integration disposition; release status separately
```

An application-generated `PASS`, green cached label, Git author string or OpenTelemetry span is supplementary evidence only. The independent process must read the actual current source and execute the pinned tests. Unknown results stay unknown.

## 4. Grade-state authority

`VERIFIED_ACCEPTED_FOR_CANDIDATE` requires: an accepted and version-pinned contract, source SHA actually observed, right suite/fixture/environment, nonzero positive **and negative** required tests executed and passed, no critical gate failure, evaluator separate from worker, and truthful evidence provenance.

Other states: `VERIFIED_REJECTED`, `INVALID_PATCH`, `INCOMPLETE`, `NO_TEST_EXECUTION`, `STALE_EVIDENCE`, `INFRA_ERROR`, `UNKNOWN_OR_AMBIGUOUS`, `SECURITY_BLOCKED`. Each accepted randomized trial remains in the outcome denominator, regardless of completion, and its real incurred costs remain in accounting.

A candidate pass does **not** assert protected integration, staged deployment, user adoption or measured AINO efficiency. To claim accepted integration, independent review must inspect the exact prospective merge state, host protection enforcement and actual observed merged SHA, under separately granted authority.

## 5. Evaluation-specific attacks and refusal behavior

- **Forged green:** Candidate code prints `PASSED` without running tests → `NO_TEST_EXECUTION` or `UNKNOWN_OR_AMBIGUOUS`; no credit.
- **Self-edited oracle:** Candidate includes changes to holdout fixture or evaluator configuration → refuse acceptance; reviewer must establish test ownership and integrity.
- **Stale source:** Reviewer tests candidate `SHA_A` but applicant submits `SHA_B` → `STALE_EVIDENCE`.
- **Cross-tenant access:** Dee obtains A private tasks → `SECURITY_BLOCKED` or rejected security requirement; never averaged into an ordinary UI score.
- **Invitation race:** Two concurrent accepts both grant membership → `VERIFIED_REJECTED` with concurrency failure.
- **Expired login:** Worker/UI ignores current session revocation → security requirement fails.
- **Prompt-injected tool log:** Text asks worker to use elevated GitHub token → trusted policy must deny, regardless of model continuation.
- **Lost Git ACK:** Trace says failed but remote ref already advanced → read-back, preserve `UNKNOWN` until reconciled; do not retry blindly.
- **Telemetry mismatch:** OTel agent ID claims QA identity, but evaluator principal unverified → no accepted verdict.
- **Missing negative cases:** All positive tests pass but evaluator did not exercise key denial cases → `NO_TEST_EXECUTION` for mandatory oracle coverage, not accepted.
