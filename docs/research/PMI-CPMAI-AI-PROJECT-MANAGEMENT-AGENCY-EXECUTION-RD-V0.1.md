## CPMAI six iterative phases → agency management opportunities

Per [PMI's six stages](https://www.pmi.org/blog/6-stages-to-run-a-successful-ai-project) and [overview guide](https://learning.pmi.org/api/courses/resources/CPMAI/CPMAI_Overview_Guide.pdf?language=undefined&version=undefined):

| CPMAI phase | Foromni operational analogue | Required independent proof |
|---|---|---|
| 1. Business Understanding | Owner-defined objective, business case, expected outcome, cost ceiling, success/stop criteria | Signed owner intent; measurable acceptance before task dispatch |
| 2. Data Understanding | Data sources, permission/access, provenance, availability, sensitivity, bias and feasibility | Source registry + lawful scope; record unknowns |
| 3. Data Preparation | Validated datasets, training/test separation or prepared tool/context inputs | Data checksums, lineage and leakage controls |
| 4. Model Development | Bounded agent/task execution and iteration, capability/tool selection | Source SHA, isolated attempts, budgets, execution receipts |
| 5. Model Evaluation | Independent evaluation vs owner acceptance criteria; failure and risk analysis | Evaluator-source binding, QA independence, benchmark and negatives |
| 6. Model Operationalization | Approved integration, release, monitoring, rollback and drift management | Protected human decision + effective runtime gates, audit and cost outcome |

**Important:** The six phases are oriented toward *AI solution delivery*, including data/model projects. Not every Foromni software patch literally trains a model. Apply the transferable governance principles proportionately, rather than force all tasks into a fictitious model-training pipeline.

## Project-management best practices to investigate

- **Outcome-first intake:** make every task show objective, customer/business value, measurable success, project owner and no-go condition; reject vague work.
- **Stage/gate transitions:** preserve distinction between proposed, scoped, built, independently evaluated, accepted and integrated; implement rules in trusted state instead of trusting agent narrative.
- **Dependency + critical path:** rank tasks by shortest path to actual accepted functionality, blocked dependencies and risk, not PR volume or agent activity.
- **Risk and assumption register:** change-controlled risks (permissions, legal data, tooling, security, cost, schedule), owner decisions and review dates.
- **Resource and cost governance:** budgets per task + per operation; track retry, review, inference, API and integration costs, not merely "tests passed."
- **Quality planning:** acceptance criteria frozen before implementation where possible; evaluator independence, test holdout and negative cases.
- **Agile iteration:** short bounded work packets, frequent evidence, defect rollback to review, explicit feedback loops after every release.
- **Human leadership and communication:** responsibility matrix across owner, coordinator, worker, independent QA and approver; clarify when agent autonomy stops and human signoff begins.
- **Benefits realization:** accepted business outcomes, time to completion, rework, escaped defects, incident rates and total true cost; prevent vanity metrics.

## Scientific comparison proposed (not run)

**PM-01 preregistered A/B experiment:** 12–30 small matched synthetic or owner-approved real development work packets; compare (A) existing freeform agent prompt vs (B) CPMAI-inspired project brief with business value, acceptance, task dependencies, risk register, cost ceiling and phase-specific gates. Hold model, codebase, budget and evaluator rubric constant. Randomize order, assess *independently accepted outcomes per total cost*, cycle time, rework, false acceptance and policy breaches. If insufficient statistical power, report descriptive outcomes rather than claims of causal improvement.

**PM-02 control-plane contract:** add optional research fields to fictional work packets: business case, value metric, data lineage, assumptions, dependency DAG, stage evidence, reviewer identity, exit/no-go conditions, monitoring/rollback owner. Do not change frozen production task schemas without separately authorized integration.

**PM-03 training ROI:** document official education syllabus, exam content, cost, effort, continuing-education requirements, alternative PMP and cybersecurity certifications, then weigh against the concrete Foromni implementation benefits. Prioritize a free official intro before paid enrollment.
