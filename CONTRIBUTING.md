# Contributing to Foromni

Welcome. Foromni is being built as a collaborative network for people, businesses, communities, developers, and intelligent systems.

We welcome thoughtful contributions to documentation, design, code, research, interoperability, community practices, and project direction.

## Before contributing

1. Read [the Founding Charter](FOUNDING-CHARTER.md).
2. Review [the initial roadmap](ROADMAP.md).
3. Search existing issues and pull requests before opening a duplicate.
4. For substantial changes, open an issue or discussion first so scope and ownership are clear.

## Ways to contribute

- Improve documentation and onboarding.
- Propose product capabilities and user research.
- Build or improve code in a focused branch.
- Develop open interfaces, integrations, and interoperability examples.
- Review security, privacy, accessibility, and maintainability.
- Help welcome contributors and make knowledge reusable.

## Pull request expectations

- Keep changes focused and explain the user or maintainer problem being solved.
- Link the relevant issue or roadmap item when one exists.
- Describe important design decisions and compatibility impacts.
- Include tests for behavior changes when appropriate; do not claim checks passed unless they were actually run.
- Document migrations, configuration changes, and operational requirements.
- Never commit credentials, private keys, access tokens, personal data, or production secrets.
- Do not introduce telemetry or data collection without clear disclosure and appropriate consent.
- Preserve attribution and respect the licenses of reused code and assets.

## Collaboration norms

Be professional, friendly, and kind-hearted. Critique proposals and implementation details, not people. Explain disagreements, welcome good-faith questions, and consider the global nature of the community.

## Security issues

Do not publish exploitable vulnerabilities or secrets in public issues. Follow [SECURITY.md](SECURITY.md) for responsible reporting.

## Decision-making

Early maintainers are responsible for repository stewardship and safe releases. Significant changes to mission, governance, privacy, security, or compatibility should be discussed openly and documented. This contribution guide is an initial working policy and may evolve with community input.
